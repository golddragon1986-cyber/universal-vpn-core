# Универсальный VPN-контейнер

## Последний релиз · 0.3b

[Комплект ARMv7 и ARM64](version/0.3b.181126.1732/universal-vpn/README.md) · [Изменения](version/0.3b.181126.1732/universal-vpn/CHANGELOG.md).

4 ноября 2026 собрана и запущена версия `0.1.0-core.20261104` на RB4011
(10.0.0.3, RouterOS 7.25, ARMv7) отдельным контейнером `universal-vpn-core`.
Рабочий `mihomo-arm32`, его конфигурация и клиентские маршруты не менялись.

## Доступ

- Панель: http://10.0.0.3:19091/
- API: http://10.0.0.3:19090/version
- MetaCubeXD: http://10.0.0.3:19090/ui/ (автоматически загружен ядром в том данных, около 8 МиБ).
- Логи: http://10.0.0.3:19091/?tab=logs
- Тестовый HTTP/SOCKS-прокси: 10.0.0.3:11080
- Тестовый DNS UDP: 10.0.0.3:15353
- Внутренний адрес: 172.31.41.2/24; шлюз: 172.31.41.1.
- Данные: `/universal-vpn-data`, mount `/etc/mihomo`.
- Root-dir: `/containers/universal-vpn-core-v2`.

Доступ ограничен существующим RouterOS-списком `mihomo-local-access`.
Автозапуск и автоматический перезапуск пока выключены. Клиентские сети на
новый экземпляр не переключены, TUN выключен. Пользовательских VPN-профилей нет.
Kill switch для будущих VPN-адаптеров ещё не реализован.

## Состав

Alpine 3.24.2, BusyBox, Python 3.14, SQLite, CA, сетевые утилиты из установленной
ARMv7-базы и Mihomo 1.19.33. Mihomo совмещает DNS/Fake IP, маршрутизацию и
поддерживаемые им протоколы; отдельный sing-box в эту основу не включён.

Панель перенесена исходниками из `../Ротеры/Mihomo-Controll-Panel`,
версия источника `0.1.2-draft.20261103`. Сохранены интерфейс, домены,
маршруты, очередь действий и восстановление. Node.js требуется только для
локальной сборки, в контейнере не запускается.

В текущем Mihomo найдены встроенные WireGuard, AmneziaWG v3/v3.1 и OpenVPN.
Добавлен импорт конфигураций этих протоколов без отдельного VPN-процесса.
Импорт WireGuard и AWG v3 с параметрами v3.1 проверен ядром на RB4011;
handshake с реальными серверами без рабочих профилей не проверялся.

## Проверки и ограничения

Проверены HTTP 200 панели, API v1.19.33, HTTP-запрос через прокси,
применение маршрута через SQLite-очередь, DNS Fake IP (`example.com` →
`198.18.0.4`), повторный запуск и сохранение настроек. SQLite integrity_check: ok.
В режиме DIRECT панель штатно выбирает redir-host; в тестовом экземпляре
выбран LOADBALANCE с единственным DIRECT, чтобы проверить режим Fake IP.
Это не VPN-подключение.

Измерения пустой основы при лёгкой тестовой нагрузке:

| Показатель | Результат |
|---|---:|
| OCI-архив | 37 153 280 байт |
| ОЗУ по RouterOS | 18.8–34.8 МиБ в отдельных замерах |
| container-size RouterOS | 89.5 МиБ, без отдельного тома данных |
| du: системные каталоги, ядро, настройки и базы | 104 996 КиБ ≈ 107.5 МБ |
| cgroup memory.max | 199 999 488 байт |
| cgroup memory.events max / oom / oom_kill | 0 / 0 / 0 |

Жёсткие требования для итоговой сборки: **≤200 МБ ОЗУ**, **≤150 МБ
распакованного образа вместе с настройками и базами**, 1–2 одновременно
используемых VPN-протокола. Соответствие при двух VPN, больших базах и длительной
нагрузке ещё не проверено. Учёт cgroup отличается от суммы RSS; файловые страницы
могут разделяться с работающим Mihomo на том же хосте.

## Сборка

`node build.mjs` создаёт `build/universal-vpn-core-armv7.tar` и
`build/BUILD-INFO.json`. Сейчас нужен локальный `build/base-armv7.tgz`: очищенный
набор системных каталогов и бинарник из установленной базы RB4011, без тома
пользовательских данных. SHA256 базы и результата фиксируются в BUILD-INFO.
Это bootstrap-сборка, ещё не независимая сборка всех зависимостей из исходников.

`vendor/panel` содержит код панели. Builder исключает старую установленную
копию панели, pycache и переносит актуальные исходники; hardlink материализуются
для совместимости импортера RouterOS. `verify.mjs` проверяет текущий экземпляр.
Сценарий `deploy-rb4011.rsc` описывает начальный импорт, не предназначен для
повторного выполнения поверх существующего контейнера. После импорта отдельно
добавлен доверенный UDP DSTNAT 15353 → 172.31.41.2:53 для проверки DNS.

Остальные целевые платформы: ARM64, x86-32 и x86-64. ARMv6 исключён.
Образы для остальных архитектур ещё не собраны.

## Журнал ядра

Вкладка «Логи» получает HTTP NDJSON-поток Mihomo через локальный API.
Уровни: silent, error, warning, info, debug. Уровень применяется сразу,
сохраняется отдельно в `rules/log-settings.json`, восстанавливается при загрузке
и повторном применении конфигурации, входит в резервную копию.
На тестовом экземпляре выбран info.

Фильтры отображения: уровень, VPN/маршрут, протокол и текст. Привязка к VPN
использует только явно записанную в сообщении цепочку `using` или маршрут ошибки
`dial ... (match ...)`. Прочие сообщения остаются системными; фактический узел
не угадывается по выбранной группе. Журналы отдельных AWG/OpenVPN-процессов
потребуют подключения при реализации этих адаптеров.

Есть пауза, очистка экрана и скачивание отфильтрованных записей. Серверный
кольцевой буфер ограничен 512 записями по 2048 символов; логи не записываются
на диск и очищаются после перезапуска панели. Уровень записи и фильтр экрана
раздельные. Для трафика нужен info/debug, warning/error показывают проблемы.

Проверены шесть unit-тестов на ARMv7, применение и сохранение уровня,
отклонение неверного уровня, реальные записи DIRECT, фильтры в браузере,
сохранение уровня после перезапуска и его включение в backup. Ссылка в шапке
на MetaCubeXD исправлена для опубликованных портов 19091/19090.

Повторный замер с журналом и MetaCubeXD: 107 052 КиБ ≈ 109.6 МБ на диске; cgroup memory.current 22 179 840 байт во время диагностики, событий max/oom/oom_kill нет. Это лёгкая тестовая нагрузка, не испытание двух VPN.

## Отказ от MetaCubeXD
По указанию владельца MetaCubeXD удалён из тестового экземпляра, настройки external-ui и автоматическая загрузка отключены, ссылка из шапки убрана. Основной интерфейс — только собственная панель с вкладкой логов. Прежние упоминания наличия MetaCubeXD описывают состояние до удаления.

## VPN и компоненты

`/?tab=vpn` заменяет вкладку «Прокси»; старый URL продолжает работать.
Добавление через очередь с проверкой `mihomo -t` до записи базы и откатом при
ошибке применения. Отключённые импортированные профили также видны в таблице.
Поддержаны URI VLESS/VMess/SS/Trojan/SOCKS/HTTP/Hysteria2, списки/подписки,
WireGuard/AWG .conf и OpenVPN .ovpn с inline-сертификатами. Для остальных
типов доступны выбор протокола и JSON-основа; окончательную поддержку
конкретных параметров проверяет установленное ядро. Неизвестные параметры
.ovpn/.conf и неподдержанные опции URI отклоняются вместо тихого отбрасывания.
Произвольные shell-хуки и чтение файлов сертификатов с роутера не выполняются.

`/?tab=components` управляет дополнительными пакетами OpenVPN CLI,
WireGuard tools, sing-box и Xray через подписанные пакеты Alpine. Архитектуру
выбирает apk. Перед установкой проверяется бюджет 150 МБ и временное место;
новая установка с превышением бюджета отменяется. Резервы для крупных клиентов
консервативны, поэтому они могут не помещаться в выбранный лимит. Установка
отдельного клиента не запускает его и не меняет маршруты. Эта версия панели
управляет соединениями через Mihomo; отдельные конфигурации Xray/sing-box не
запускаются этой формой.

Mihomo обновляется штатным API ядра. Его нельзя удалить из работающей основы,
поскольку он обслуживает DNS и маршрутизацию. Встроенные протоколы обновляются
вместе с ним; они не являются отдельными удаляемыми бинарниками.
Само обновление Mihomo на другую версию в рамках этой проверки не запускалось.

Проверки: 11 unit-тестов на ARMv7; реальный цикл install/update/remove для
WireGuard tools через очередь; импорт SOCKS, WireGuard и AWG v3/v3.1; отказ
неверного порта до изменения базы. Проверочные соединения удалены. Результаты
в build/vpn-integration.json и build/components-integration.json.

## Sing-box REALITY / ML-KEM — 4 ноября 2026

Собран и установлен `sing-box 1.14.4-local.mlkem1` с локальным исправлением
совместимости REALITY / X25519MLKEM768. Профили из остановленного рабочего
контейнера сохранены в приватном `/etc/mihomo/clients/sing-box.json`, процесс
запускается вместе с тестовым контейнером. В панели доступны `SB-SV` и `SB-FL`;
в балансировку они не включены. Проверка соединений работает независимо от
участия в балансировке.

В смешанной серии: 30/30 на обоих; в ускоренной — SV 18/20, FL 20/20.
Неверный ключ отклонён. Полный отчёт: reports/sing-box-mlkem-20261104.md.
Исправление и воспроизведение: patches/README.md. Локальная сборка имеет
ограниченный набор расширений (`with_utls`) и не заменяет весь функционал
официального полного binary. Автообновление через apk поверх неё блокируется.

Лимит диска **временно отключён** по указанию владельца; старые оценки и
требование 150 МБ ниже/выше описывают предыдущий этап. Настройка —
`rules/resource-limits.json`, disk_limit_bytes=0; входит в backup.
Лимит ОЗУ остаётся 200 МБ. Итоговый замер: около 133.6 МБ на диске,
29.5 МБ memory.current в покое; это не гарантия пиков при произвольной нагрузке.

`node build.mjs` включает локальный binary, если есть
build/sing-box-1.14.4-mlkem-armv7. Секретные конфиги в образ не включаются.
При необходимости сборочный предел задаётся IMAGE_MAX_BYTES; по умолчанию
не применяется. Рабочий mihomo-arm32 остаётся остановленным.
