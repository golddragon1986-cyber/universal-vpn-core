# hAP ac³: Cloudflare, рост числа соединений

Методика как у RB4011: внешний Windows-компьютер → HTTP CONNECT proxy 192.168.99.1:11080 → SV-inbound → Cloudflare HTTPS __down. Канал временно зафиксирован только для тестового домена. Здесь движок sing-box, на RB4011 — Mihomo; сравнение не изолирует аппаратную разницу. На соединение запрошено 32 МиБ, максимальное время 25 секунд; при таймауте учтены фактически принятые байты. Путь SV-inbound / CHANNEL-SV-inbound подтверждён API на обеих ступенях.

| Соединения | Получено, байт | Время, с | Мбит/с суммарно | CPU средняя по снимкам | CPU пик | Пик ядра |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 33 554 432 | 17,01 | 15,78 | 50,75% | 67% | 93% |
| 4 | 109 285 299 | 25,27 | 34,60 | 64,5% | 97% | 100% |

На четырёх потоках заданный порог >90% общей CPU достигнут одним снимком (97%), дальнейший рост прекращён. Это пиковая нагрузка, не непрерывные 97%: остальные снимки 77/35/42/66/70%. Два потока полностью скачали 32 МиБ; два завершились по установленному лимиту 25 секунд после 29 376 827 и 12 799 608 байт. Все четыре получили HTTP 200. Скорость рассчитана по фактическим байтам и общему времени.

CPU измерялся короткими SSH-снимками RouterOS. На первой ступени также выполнена короткая проверка активного движка через container shell, которая могла повлиять на CPU. Длительной диагностической сессии не было. Временное правило удалено, постоянная конфигурация восстановлена; панель проверена после теста.
