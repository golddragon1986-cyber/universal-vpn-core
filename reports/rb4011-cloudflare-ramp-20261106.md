# RB4011: увеличение числа соединений до CPU >90%

Внешний компьютер → HTTP CONNECT proxy 10.0.0.3:11080 → Mihomo → SV-inbound → Cloudflare HTTPS __down. На соединение 32 МиБ, ответы HTTP 200 и полный объём подтверждены для всех потоков. Краткая API-проверка подтвердила цепочку SV-inbound / CHANNEL-SV-inbound на каждой ступени. Длительная /container shell не удерживалась. CPU получен короткими SSH-командами RouterOS /system resource; значения являются снимками, не непрерывным профилем.

| Параллельные соединения | Объём | Время, с | Суммарно, Мбит/с | Общая CPU | Максимум ядра |
|---|---:|---:|---:|---:|---:|
| 1 | 32 МиБ | 3,30 | 82,3 | не успели снять | — |
| 4 | 128 МиБ | 3,34 | 321,9 | не успели снять | — |
| 8 | 256 МиБ | 3,86 | 555,6 | 56% | 60% |
| 16 | 512 МиБ | 8,10 | 530,2 | 90% | 100% |
| 32 | 1024 МиБ | 15,17 | 566,4 | 93% | 94% |

На 32 соединениях достигнут заданный порог общей CPU >90%, дальнейшее увеличение прекращено. Временное правило Cloudflare удалено, постоянная конфигурация восстановлена. Измеренное время включает короткую проверку пути и CPU; особенно на коротких ступенях 1/4 скорость может быть занижена относительно времени самой передачи. На ступенях 8/16/32 получен один CPU-снимок на ступень.

Начальный запрос 256 МиБ на соединение был отвергнут Cloudflare HTTP 403 и исключён; рабочий тест повторён с 32 МиБ. Результат существенно выше предыдущего теста (6,3/21,3 Мбит/с); причина различий не установлена. Эти данные показывают текущую скорость выбранного пути, а не гарантированную постоянную пропускную способность или предел шифрования.

Сырые данные: build/rb4011-ac3-settings/cloudflare-ramp.json.
