# Скорость VPN на hAP ac3 — 6 ноября 2026

## Вывод

В проверенной нагрузке ограничивает процессор, а не память. Через SV
получено 33.28 Мбит/с в четыре HTTP-потока при средней загрузке CPU 97.1%.
Это результат данного роутера, текущих VPN-профилей и маршрута до Selectel,
а не универсальный предел протокола или канала.

## Методика

Загрузка https://speedtest.selectel.ru/100MB и http://speedtest.selectel.ru/100MB
внутри контейнера, без записи данных на USB. Один и четыре TCP-потока,
до 18 секунд на фазу, суммарный объём ограничен примерно 192 МиБ на фазу.
Полные 100-МиБ одиночные загрузки заканчиваются раньше.

Временные mixed-listeners привязаны к 127.0.0.1 и принудительно выбирают
DIRECT, CHANNEL-FL либо CHANNEL-SV-inbound. Рабочие клиентские правила не
переключались. Проверены цепочки в API Mihomo. По окончании загружена штатная
конфигурация; тестовые порты закрыты. Это проверка загрузки, не отдачи.

Python получает данные внутри контейнера и сам расходует CPU. Поэтому HTTP
контроль исключает TLS тестового клиента, сохраняя шифрование самого VPN.
В HTTP SV/4 тестовый Python занимал ~24% одного ядра, Mihomo ~172%.
Данные /proc/stat сверены с отдельными замерами CPU RouterOS по ядрам.

## Результаты

| Выход | HTTPS 1 поток | HTTPS 4 потока | HTTP 1 поток | HTTP 4 потока |
|---|---:|---:|---:|---:|
| DIRECT через ядро контейнера | 54.74 | 99.39 | 84.59 | 151.05 |
| SV-inbound | 7.56 | 19.46 | 14.46 | 33.28 |
| FL | таймаут TLS | таймаут TLS | таймаут | таймаут |

Скорости в Мбит/с, включая установку соединений. FL не передал полезных
данных от Selectel; это не измерение его предельной скорости. Другая
ранняя проверка Cloudflare получила HTTP 403 и в результаты не включена.
Второй источник Hetzner/OVH не оказался доступным для пригодного контроля.

На HTTP SV/4: CPU 97.1% в среднем, ядра 99.8/98.2/93.8/96.5%, iowait 0.1%.
На HTTP DIRECT/4: CPU 95.9%, 151.05 Мбит/с. Это DIRECT через контейнер,
а не чистый FastTrack WAN; скорость тарифа этим тестом не измерялась.

## Память

- SV HTTP: пик memory.current 94.7 МиБ из лимита 160 МиБ.
- Общий пик во всех полезных фазах: около 105 МиБ.
- Swap контейнера: ~0.93–0.98 МиБ, рост менее 0.1 МиБ.
- memory.events high/max/oom/oom_kill не увеличились.
- Linux MemAvailable в SV HTTP/4 не ниже ~110.8 МиБ (включает освобождаемый cache).
- После теста RouterOS free-memory ~61.5 МиБ.

Выделение дополнительного swap не должно улучшить измеренную скорость.
Для большей скорости целесообразно отдельно сравнить более лёгкий профиль/
протокол или более производительный роутер; это требует новых измерений.
Профили и параметры производительности в рамках теста не менялись.

## Дополнение: в обход контейнера

По запросу владельца выполнен RouterOS /tool fetch с src-address=5.23.108.48
по реальному IP 188.93.16.211, HTTP Host speedtest.selectel.ru, output=none.
DNS/Fake IP, ядро контейнера и VPN в пути тестовых загрузок не участвовали.
Сам контейнер продолжал штатно обслуживать клиентов.

- Один файл 104857636 байт за 6.122 секунды: около 137 Мбит/с.
- Четыре файла параллельно, суммарно 419430544 байта за 12.000 секунды:
  около 280 Мбит/с; в длительность включён запуск четырёх SSH-команд.
- Во время основной загрузки CPU RouterOS обычно 30–50%, пик 50%;
  одно ядро достигало 88%, в основном IRQ. После теста CPU вернулся к 5–8%.
- Это загрузка самим роутером, а не измерение максимальной LAN→WAN
  производительности FastTrack и не VPN без контейнера.
