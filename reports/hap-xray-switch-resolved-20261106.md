# hAP ac3: откаты при выборе Xray устранены в проверенной конфигурации

## Причина и проверки

Панель успешно сохраняла и применяла конфигурацию, затем откатывала смену на
этапе проверки соединения через Mihomo: HTTP 504 при таймауте 5000 мс.
Ранее исходное исключение скрывалось общим сообщением. Теперь отображаются
этап и безопасно очищенная причина; секреты исходного профиля скрываются.

Штатный randomized Xray 26.10.31 в изолированной проверке не обеспечивал
ML-KEM. Первоначальный обход Chrome согласовывал ML-KEM, но не проходил
стабильно под рабочей нагрузкой. Изолированная связка Mihomo→Xray сама по
себе проходила 5/15-секундные проверки, поэтому общее отключение проверки
или произвольное увеличение таймаута не применялось.

Firefox в двух свежих запусках прошёл 12/12 HTTPS-запросов, с подтверждённым
native Xray ML-KEM=true для всех двенадцати handshake. Конвертер теперь
выбирает Firefox для Xray при исходном randomized/randomizednoalpn и
REALITY/ML-KEM; исходная каноническая запись сохраняется. Успешное сообщение
панели явно сообщает engine-specific TLS-профиль.

## Сквозная проверка через панель

После явного разрешения владельца на временное переключение рабочих VPN:

- №30 FL → Xray: done, 20.73 с.
- №31 SV-inbound → Xray: done, 25.37 с.
- Под обычным трафиком оба канала оставались в LOADBALANCE.
- SV: 12/12 HTTP 204, 4 параллельных потока; provider delay 799/494/537 мс.
- FL: 12/12 HTTP 204, 4 параллельных потока; provider delay 1066/1025/1012 мс.
- memory.events high/max/oom/oom_kill = 0 за проверенный запуск.

Рабочие соединения после временного теста возвращаются на sing-box штатной
очередью панели. История №32/33 фиксирует обратный переход.

## Лимиты памяти

При одновременной работе Mihomo, sing-box, Xray и валидатора возрастал
memory.events high из-за прежнего мягкого лимита 120 МиБ. Лимиты изменены
на high=160 МиБ, max=190 МиБ (менее 200 МБ), swap-max=256 МиБ.
Это убрало мягкий reclaim, но само по себе не устранило откат с Chrome.
Основное результативное изменение для наблюдавшегося сбоя — Firefox.
Изменение лимитов RouterOS перезапустило контейнер, что отдельно прервало
действие №27; эта попытка не считается сетевым отказом.
