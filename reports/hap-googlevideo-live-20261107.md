# ac³: наблюдение высокоскоростного Googlevideo

Read-only наблюдение 24 снимка примерно за минуту, интервал 2,5 секунды; CPU/интерфейсы/conntrack каждые два снимка. Настройки не менялись, диагностический debug не включался. Клиент 192.168.99.241, TCP Redir. Из API сохранялись только Googlevideo, без URL и токенов.

## Подтверждённые факты

Основной передающий поток rr5---sn-aj4g55-j5.googlevideo.com имел один и тот же id 106c523d-bcc4-4091-afa3-8d06028f2353 всю минуту. Цепочка неизменна: SELECTOR → CHANNEL-SV-inbound → SV-inbound. Тип tcp/Redir; правило RU-BLOCKED. В начале также было малое соединение другого Googlevideo с 5785 байтами и без значимого прироста; оно исчезло. Рост основной скорости нельзя объяснить суммированием множества видимых передающих Googlevideo-потоков.

Скорость основной сессии по приросту её download counter: 101,93 / 118,36 / 139,63 / 109,63 Мбит/с в первой пачке и 94,78 / 200,41 / 164,95 Мбит/с в следующей; позднее 190,69 Мбит/с. Между пачками — паузы буферизации с нулевым приростом. За окно counter вырос 741 223 734 → 1 110 552 849 байт (369 329 115 байт). Это короткие интервальные скорости, не обещание непрерывных 200 Мбит/с.

CPU по снимкам в первой высокоскоростной пачке 51–53%, во второй 55%; максимум за всё окно 55%. Между пачками 5–12%. Короткие снимки CPU не являются полным непрерывным профилем.

На паре RouterOS-снимков при CPU 53%:
- ether1 RX 150,68 Мбит/с;
- veth-universal RX/TX 134,83 / 141,67 Мбит/с;
- reply bytes одного внешнего TCP-соединения контейнера 172.31.41.2 → VPN server:443, src-port 43806: 137,36 Мбит/с.

На следующем высоком участке с CPU 55%:
- ether1 RX 160,64 Мбит/с;
- veth-universal RX/TX 160,37 / 169,39 Мбит/с;
- reply bytes того же внешнего VPN-соединения: 171,27 Мбит/с.

Интервалы API (~2,5 с) и RouterOS (~5 с) отличаются и снимки делаются последовательно, поэтому эти значения нельзя сравнивать как синхронные точные равенства. Их корреляция и цепочка Mihomo подтверждают передачу по VPN, а не возврат ответа непосредственно на основной IP.

## FastTrack и интерпретация

На ac³ включено правило forward fasttrack-connection established,related. Внешние соединения к VPN:443 отмечены fasttrack=true. Это может снижать расходы RouterOS на пересылку. FastTrack не отменяет прохождение трафика через сам VPN и не доказывает внутренний zero-copy режим Vision.

Наблюдение опровергает предположение о постоянном пределе одного VPN-соединения 20 Мбит/с для этого видео. Vision/особенности TLS-передачи и FastTrack — возможные составляющие эффективности. Их отдельный вклад и момент перехода Vision по этим read-only данным не определены; debug/pprof не включались, конфигурация не менялась. Предыдущий профиль HTTP Selectel не эквивалентен HTTPS Googlevideo.
