# hAP ac3: снижение нагрузки TUN

6 ноября 2026. По разрешению владельца тестировался один SV-inbound,
FL временно исключён из балансировки штатным действием панели №34.
Оба VPN сохраняли движок sing-box и исходные профили.

## Методика

Один TCP-поток, HTTP Range bytes=0-33554431 файла
http://speedtest.selectel.ru/100MB. Каждый ответ HTTP 206, ровно 32 МиБ.
Для TUN загрузку выполнял RouterOS /tool fetch, src-address=192.168.99.1,
output=none. DNS вернул 198.18.1.83, маршрут 198.18.0.0/16 шёл в контейнер.
Временное правило только для тестового домена принудительно выбирало
CHANNEL-SV-inbound, поэтому это VPN, а не MATCH,DIRECT.

CPU измерялся по /proc/stat и /proc/PID/stat каждые 0.5 секунды, вместе с
cgroup CPU, памятью, swap и memory.events. В интервал мониторинга входит
небольшая задержка запуска/завершения SSH-команд. Загрузки на USB не писались.
Обычный клиентский трафик не останавливался, поэтому результаты — короткое
сравнение в реальных условиях, а не лабораторный гарантированный предел.

## Результаты

| Вариант | Секунды | Мбит/с | CPU Mihomo, 100%=одно ядро | CPU-секунды хоста / 32 МиБ |
|---|---:|---:|---:|---:|
| gvisor, первый | 31.60 | 8.50 | 93.5% | 94.70 |
| system | 22.25 | 12.06 | 55.0% | 59.23 |
| mixed | 18.28 | 14.68 | 62.2% | 57.43 |
| gvisor, повтор с тёплым DNS | 27.21 | 9.87 | 108.8% | 85.10 |

Относительно повторного gvisor: mixed быстрее в 1.49 раза, CPU-время хоста
на одинаковый объём меньше на 32.5%. CPU-время самого Mihomo на объём
уменьшилось примерно на 58%. Абсолютная скорость не сопоставляется напрямую
с прежним пользовательским тестом на другом файле/сервисе.

Отдельная диагностика через существующий HTTP/mixed-прокси Mihomo
192.168.99.1:11080 без TUN дала 30.29 Мбит/с. Для неё curl работал на ПК
192.168.8.134 через IPsec, а не /tool fetch на hAP. Клиент и сетевой путь
отличаются; это ориентир оставшихся накладных расходов, не чистое A/B.
Этот тест всё ещё содержит цепочку Mihomo→SOCKS→sing-box: непосредственный
порт sing-box наружу не открывался. Новые слушающие порты не добавлялись.

За измеренные фазы нет прироста memory.events high/max/oom/oom_kill.

## Сохранённый результат

- TUN stack=mixed: TCP использует system, UDP сохраняет gVisor.
- Изменены runtime, candidate, template/default_config.yaml,
  rules/panel-managed-template.yaml. Обновлён configure-hap-fakeip.py в проекте.
- Резерв прежних четырёх конфигов на USB:
  /etc/mihomo/tun-optimization-20261106/.
- Временное правило Selectel удалено. Основной маршрут LOADBALANCE.
- FL возвращён в балансировку штатным действием №35.
- Оба узла: client=sing-box, balance=true; финальная проверка 572/1029 мс.
- DNS Telegram вернул 198.18.0.42, HTTPS с LAN-адреса hAP: HTTP 200.
- Изменений GOGC, MTU, CPU frequency, шифрования и VPN-профилей не делалось.
