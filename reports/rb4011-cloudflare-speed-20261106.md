# Повторный тест RB4011: Cloudflare

Внешний Windows-компьютер → HTTP CONNECT proxy 10.0.0.3:11080 → Mihomo → SV-inbound → https://speed.cloudflare.com/__down. GET bytes=33554432, 32 МиБ на поток; 4 потока — 128 МиБ. Во время скачивания нет открытой длительной /container shell. Короткой проверкой API подтверждены HTTPS и цепочка SV-inbound → CHANNEL-SV-inbound для всех потоков. Временное правило домена после тестов удалено, постоянная конфигурация восстановлена.

| Потоки | Объём | Время | Скорость |
|---|---:|---:|---:|
| 1 | 32 МиБ | 42,46 с | 6,32 Мбит/с |
| 4 | 128 МиБ | 50,39 с | 21,31 Мбит/с суммарно |

Все ответы HTTP 200, весь ожидаемый объём получен. Первоначальная попытка остановилась на CRYPT_E_REVOCATION_OFFLINE; успешные тесты использовали curl --ssl-revoke-best-effort, проверка TLS-сертификата сохранена.

Краткие снимки CPU во время внешних загрузок: 6/4/7/14%, 3/8/18/9%, 7/5/12/9% по четырём ядрам. Насыщения CPU не наблюдалось. Следовательно, предыдущие 100% одного ядра с открытой /container shell не доказывают процессорный предел VPN. Причина текущей скорости этим тестом не локализована: в измерение входят внешний компьютер, путь до прокси, VPN-канал и Cloudflare. Это тест прокси, а не прозрачного перенаправления трафика LAN.
