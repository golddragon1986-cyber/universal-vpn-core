# hAP ac³: 8 и 16 потоков Cloudflare

Внешний компьютер → HTTP CONNECT proxy 192.168.99.1:11080 → SV-inbound/sing-box → Cloudflare HTTPS. Тест как в предыдущей серии: запрос 32 МиБ на соединение, лимит каждой загрузки 25 секунд. Пропускная способность рассчитана по фактически полученным байтам за общее время. Все потоки получили HTTP 200 и данные; завершились по заданному лимиту curl (код 28), поэтому полного файла не ожидалось. Путь через SV-inbound подтверждён API на обеих ступенях. Длительной container shell не было.

| Потоки | Получено, байт | Общее время | Суммарно | CPU |
|---|---:|---:|---:|---|
| 8 | 164 714 535 | 25,28 с | 52,11 Мбит/с | 5 снимков: 97/91/61/85/79%; среднее 82,6%, пик 97% |
| 16 | 197 600 923 | 26,77 с | 59,05 Мбит/с | получен один снимок: 98%; ядра 100/98/99/95% |

Прирост скорости от 8 к 16 потокам около 13,3%. Снимок CPU на 16 потоках показывает насыщение процессора; длительное среднее по единственному снимку определить нельзя. На обеих ступенях отдельные ядра достигали 100%.

Обе ступени выполнены по прямому запросу пользователя несмотря на CPU >90%. Временное правило удалено, постоянная конфигурация восстановлена. Панель после тестов проверена.
