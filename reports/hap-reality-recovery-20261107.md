# ac³: SV-inbound -1 и REALITY authentication failed

Активный Mihomo, SELECTOR=CHANNEL-SV-inbound, CHANNEL-SV-inbound=SV-inbound, LOADBALANCE содержит только CHANNEL-SV-inbound. Файл провайдера совпадает с canonical profile. Ключи/UUID/адреса не менялись. RouterOS 00:25:29 07.11.2026 Europe/Moscow согласуется с UTC 21:26:12 06.11.2026 (разница между последовательными измерениями); NTP выключен, но существенного сдвига времени в момент диагностики нет.

Основной процесс возвращал healthcheck HTTP 503. В изолированном Mihomo тот же профиль с randomized дал HTTPS 204 gstatic и 200 telegram.org; с chrome — также 204/200. С firefox — ошибки REALITY authentication failed и EOF. Первоначальная серия без ожидания готовности порта имела connection errors и не используется для выводов. Пользовательский профиль не изменялся.

Выполнен перезапуск только основного ядра через HUP действующего supervisor. После этого исходный randomized профиль вернул 648 мс. Повторная проверка основного процесса: healthcheck 840/478/541/486/523 мс; HTTPS telegram.org 200/200/200; панель HTTP 200.

Это подтверждает восстановление без изменения ключей и профиля. Наблюдения указывают на зависимость сбоя от состояния процесса/генерации TLS fingerprint; точный механизм ещё не локализован, долговременную стабильность randomized эти короткие проверки не доказывают. После предыдущего профилирования требовалась не только проверка панели, но и реальная проверка VPN; теперь она выполнена. Профиль firefox не применён к рабочему провайдеру.

SV-inbound оставлен Mihomo/randomized, FL не включался, swap выключен. Запрос telegram.org не является проверкой MTProto-сессии конкретного DC 149.154.167.51.
