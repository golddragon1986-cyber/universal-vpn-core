# hAP ac³: 8 потоков через два канала

Временное правило только тестового домена → LOADBALANCE, действующие SV-inbound и FL (sing-box). После обоих запусков постоянная конфигурация восстановлена.

Cloudflare: запущено 8 запросов по 32 МиБ. Четыре получили HTTP 429 (1 байт), четыре HTTP 200 с полными 32 МиБ. Во время снимка API были видны только четыре FL. Первый тест отвергнут как некорректный для 8 работающих потоков; старое условие проверки ошибочно засчитало упоминание SV-inbound в traceback. В повторном тесте проверка исправлена: требуются обе CHANNEL-цепочки без traceback и успешные HTTP-ответы всех потоков.

Selectel: 8 HTTP Range-запросов по 32 МиБ, предел 25 секунд. API подтвердил ровно 4 цепочки SV-inbound/CHANNEL-SV-inbound/LOADBALANCE и 4 FL/CHANNEL-FL/LOADBALANCE. Четыре потока получили HTTP 206, суммарно 88 656 122 байт; четыре не получили заголовков/данных за 25 секунд (HTTP 0, curl 28). Общее время 26,48 с, фактическая скорость 26,79 Мбит/с. Это не результат восьми успешно передающих потоков; соответствие конкретных неответивших запросов каналам данным снимком не установлено.

CPU по шести снимкам: 95/93/93/92/91/91%, среднее 92,5%, пик 95%, отдельные ядра до 100%. Значит двухканальный сценарий в этом запуске насыщал CPU; источник отсутствия ответов четырёх запросов не локализован. Настройки и активные клиенты не менялись, временное правило снято, панель после теста HTTP 200.

Артефакты: build/hap-ac3-clean/cloudflare-two-channels-8.json и selectel-two-channels-8.json.
